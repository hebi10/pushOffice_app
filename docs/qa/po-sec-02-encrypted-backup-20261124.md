# PO-SEC-02 — 암호화 백업 및 복원 (2026-11-24)

- 기존 일반 UTF-8 JSON v1과 SHA-256 체크섬 유지. 일반 JSON은 비암호화임을 명확히 표시. 신규 .pobak은 AES-256-GCM, 파일별 무작위 16-byte salt/12-byte nonce, PBKDF2-HMAC-SHA256 600,000회, 128-bit GCM 태그, 고정 버전 헤더 AAD. 외부 암호 라이브러리 추가 없음.
- 비밀번호 12~128자, 저장 전 재확인, 입력 마스킹, 자동완성 끔, 완료·취소·탭 이동 시 입력 상태 제거. 영구 저장/전송/로그 금지. 잊어버리면 복구 불가. 불변 문자열·런타임 메모리는 완전 삭제 보장 불가.
- 암호화는 저장 위치 선택 전 진행. 복원은 파일 헤더 확인 → 비밀번호/GCM 검증 → 기존 JSON 무결성·스키마 검증 → 신규/중복 건수 미리보기 → 사용자 선택 → SQLite 트랜잭션. 복호화 실패 시 일정/설정 변경 없음.
- 일반 JSON 최대 8 MiB(UTF-8), 암호화 봉투 최대 12 MiB, 원문 한도 동일. 초과 파일은 읽기/쓰기 차단; 내용 검증 전에 원본 저장 위치의 파일을 열지 않음(시스템 파일 선택창이 생성한 빈 문서 및 외부 제공자 쓰기 실패의 원자성은 보장하지 않음).
- 최근 성공한 백업 시각/종류만 로컬 보관. 파일 선택 취소/실패는 최근 기록 변경하지 않음. 파일 저장 성공과 기록 저장 실패를 구분. 파일의 존재/원격 동기화 지속 확인은 별도.
- 설정 복원 및 실패 롤백을 기존 settings queue 안에서 직렬 처리; SQLite 기존 ID 보존 및 중복 건너뛰기 유지. 다른 앱 설정 수정과 복구가 롤백 사이에 끼지 않음. 알림 예약 실패와 데이터 저장을 구분. 프로세스 종료에 걸친 SQLite+AsyncStorage 원자적 트랜잭션은 아님.
- 단위: 잘못된 비밀번호·암호문 변조·잘못된 버전/길이·고정 독립 표준 암호화 벡터·한글/랜덤 salt/nonce·최근 기록·롤백 검증.
- API29 선별 계측: Android 암호 제공자 및 파일 스트림, 기존 SQLite 복원·원자적 import 검증. 실제 SAF/Drive 파일 제공자·앱 종료·다른 실기기 간 백업·복원은 최종 실기기 QA 필요.
- 기존 전체 3환경 최종 QA 정책, Play 업로드·서명 설정은 그대로 유지. 이번에는 배포 없음.
