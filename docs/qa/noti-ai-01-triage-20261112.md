## 1. 검증된 이전 기준선

2026-11-12 10:00 Asia/Seoul 기준 합성 알림 60건의 실제 Kotlin 후보 필터·일정 파서 테스트 결과(JSON GitHub Actions artifact, NOTI-AI-00):
- 명확한 일정 21/24 인식(87.5%); 불완전 일정 0/12(0%).
- 최종 후보 TP 21, FP 10, FN 15, TN 14.
- 최종 정밀도 21/31=67.7%, 일정 의도 전체 재현율 21/36=58.3%.
- 잘못 추천한 비일정 알림 10개: 방송·할인·기사·배송·시스템 점검·취소·뉴스 등.
- 민감 키워드 합성 알림 10/10 파싱 전 차단.
- **이 수치는 가상 문장 60개에 대한 코드 실행 결과이며 실제 카카오톡/SMS 운영 인식률이 아니다.**

## 2. 핵심 구현

### N01. 판정 3종

- `confirmed_candidate`: 원문에서 확인된 미래 날짜·시간, 유효한 반복·제목, 개인 일정 의도까지 모두 만족한 경우에만 일정 후보로 저장.
- `needs_confirmation`: 날짜·시간 누락, 정확한 오전·오후 미상, 모호한 만남·예약·행사 등은 시작 시각 없이 후보로 저장. `startAt=null` 사용. **0/1970년 또는 임의 09:00으로 날짜를 대체하지 않는다.**
- `discard`: 민감 키워드/OTP·은행·금융 등, 취소·연기·무산, 뉴스·방송·배송·광고·점검·쿠폰 등, 또는 일정 의도·시간 단서 부족 시 저장하지 않음.
- 별도 생성형 AI 추론 없이 Kotlin 로컬 규칙·`ScheduleParser.parse`로 처리. Android 시스템과 사용자가 기능을 켠 경우에만 이벤트 처리.

### N02. 자연어 보강

- 기존 정규식의 `금요일`, `토요일` 등 단독 요일 누락 및 `매월 31일`, `매년 2월 29일` 등의 반복 표현을 인식.
- `3시에 만나자`와 같이 오전/오후가 불명확한 1~12시 표현은 반드시 사용자 확인. `오후 3시`, `15:00`, `15시` 등의 명확한 표현만 현재 파서가 확인한 날짜와 함께 확정.
- 현재 `ScheduleParser` 및 `AiScheduleTime.validated`의 날짜·시간·시간대 검증은 변경하지 않음. 기존 `NotificationSuggestionPolicy.candidate`의 엄격한 구 버전 동작과 NOTI-AI-00 기준선도 보존.

### N03. 데이터 및 호환성

- `NotificationSuggestion`에 `triage` 명시, `startAt: Long?` 로 확장.
- 기존 `SharedPreferences` 기록은 `triage` 필드가 없어도 `confirmed_candidate`로 읽고 기존 타임스탬프 보존. 새 불완전 후보는 JSON null로 저장·복원.
- `confirmed_candidate`는 유효한 미래 시각이 있어야 저장, `needs_confirmation`은 시작 시각이 **반드시 null**이어야 저장.
- 동일 알림은 기존 해시/중복 키로 방지. 불완전한 문장 내용이 같더라도 서로 다른 대화의 알림을 단일 후보로 잘못 합치지 않음. 확정 후보의 동일 제목·시각은 기존처럼 중복 방지.
- 기존 최대 24건·48시간, 기능 기본 OFF, Android 권한 사전 확인·사용자 별도 동의, OFF 시 후보 기록 삭제, 승인 전 SQLite 일정 미저장 모두 유지.
- **기존 v1 동의는 날짜·시각이 모두 있는 후보 처리에만 해당했으므로 새 분류 범위는 자동 승계하지 않는다.** 저장된 동의 버전이 2가 아니면 알림 수집을 비활성화하고, 사용자가 새 고지·동의 화면을 다시 확인해 켠 경우에만 `consent_version=2`를 저장한다. 기존 후보 기록은 48시간 보관 정책을 따르고, 명시적으로 기능을 끄면 삭제한다.
- 알림 전체 대화 이력, 임의 서버 전송, 별도 자동 저장, AI 백그라운드 실행 없음.

### N04. 화면 및 검토

- 추천 카드에서 시작 시각이 null이면 `날짜·시간 확인 필요`를 표시하며 타임스탬프를 형식화하지 않음.
- 불완전한 후보는 기존 네이티브 일정 확인 화면을 **날짜·시간이 빈 상태로** 실행. 사용자가 날짜 선택·시간 선택·수정한 뒤 기존 `ScheduleTime.validate`와 글로벌 저장 락의 중복 검사·승인 버튼을 통과해야 저장.
- 확정 후보의 `기기 AI로 다시 분석` 기능은 유지하지만, 날짜·시간이 확인되지 않은 후보에는 활성화하지 않음. 기존 Gemini Nano/LiteRT 모델·SHA256·알림 원문 전송 방침 변화 없음.
- 기존 `검토 후 저장`과 `거절·삭제` 버튼 유지. 불완전 후보는 `날짜·시간 확인` 버튼으로 구분.

## 3. 회귀 테스트·정량 목표

- NOTI-AI-00과 **동일한 합성 알림 60개**로 새 3단계 결과 검증(다른 내용이나 라벨로 유리하게 변경하지 않음).
- 명확한 일정 24개는 날짜·시간·반복까지 실제 파서 결과가 예상과 일치해야 함.
- 불완전 일정 12개는 모두 `needs_confirmation`이어야 하며 startAt이 null이어야 함.
- 일정 무관 14개 및 민감 10개는 `discard`이고 원문/시각을 후보로 전달하지 않아야 함.
- 한 문장에 대한 확정 시각과 오전/오후 구분·과거 날짜·반복·윤년·메시지 중복·레거시 후보 호환성 회귀를 포함.
- Android API29 계측에서 실제 `JSONObject` 저장·복원 시 레거시 `startAt` 보존, 새 `startAt=null` 라운드트립, 이전 동의 버전의 자동 활성화 차단을 `NotiAi01PersistenceTest`로 확인한다.
- **단위테스트 합격은 실제 60개 합성 문장 성능만 입증**. API29/35/36·삼성 One UI·카카오톡 알림 본문 숨김·사용자 권한 철회·실제 배터리 소모는 별도 실기기 QA가 필요.
- 실제 사용자 데이터 수집/프로덕션 로그/새 의존성 추가 없이 검증.
