# PO-CI-10 — Gradle 의존성 429 복구
- 확인된 실패: PR #92 (45337934039), PR #96 (45340299149). React settings 플러그인 구성 시 gson 2.9.1 Maven GET HTTP 429, 계측 이전 중단.
- 기존 검증 명령·Gradle 버전·저장소·배포 정책은 변경하지 않음. CI 검증 호출에서만 원래 인수를 그대로 전달하는 최대 3회 wrapper 적용. 공식 Maven/Gradle 호스트의 명시적 GET 429 + 의존성 해석 오류 조건에서만 30/60초 후 재시도. 이미 테스트 실행 단계가 시작됐거나 컴파일 오류·테스트 실패이면 즉시 원래 실패 코드 반환. 다른 HTTP 오류와 SHA 검증 실패는 성공으로 처리하지 않음.
- 실제 Play 배포 및 서명 워크플로는 변경하지 않음. 배치 최종 main QA 및 필수 CI 정책 유지. Node 합성 shell fixture에서 복구/재시도 한도/원래 인수/실패 전파를 검사. 실제 Android 의존성 서비스의 가용성을 보장하지 않음.

## 후속 검증 오류 수정
- #96/#97 최신 CI 실패 로그 `result[1]: unbound variable`: `"$PIPESTATUS"`는 첫 원소만 확장하므로 두 파이프라인 종료 코드를 보존하지 못했다. Bash 배열 전체를 `"${PIPESTATUS[@]}"`로 즉시 캡처하며 길이 확인을 추가한다.
- 로컬 Bash 5.2.37에서 성공, 429 복구, 3회 상한, 이미 테스트 시작, 컴파일 실패, 허용하지 않는 URL/HTTP 404, 일반 오류 및 인수 보존 10개 합성 사례를 실행해 모두 성공 확인. CI에는 성공과 로그 쓰기 실패 회귀도 추가한다. 실제 GitHub Android 검증 성공은 새 head 실행 결과를 확인해야 한다.
