# PO-SEC-01 — 외부 브리핑 API 보안 강화 (2026-11-24)

## 개발 범위
- 기본 서버 OFF, 승인된 기존 Firebase UID 목록(최대 50)과 revocation 검사 ID 토큰이 모두 필요. 신규 계정 생성·자동 익명 로그인 없음. 기존 계정이 없는 새 설치는 로컬 기능을 그대로 사용. 운영 App Check/Play Integrity 도입은 공개 활성화 전 별도 과제로 남긴다.
- 두 HTTP 엔드포인트 모두 엄격한 입력 스키마 및 인증, 공통 Firestore 트랜잭션 승인 후에만 외부 API 호출. 저장소 장애/불명 상태는 fail-closed. Firestore 클라이언트 접근 차단.
- UTC 기준 일일 전역 12회, 계정별 4회, 분당 전역 3회/계정별 1회, 일일 주식 제공자 예상 최대 호출 24회(종목 수 × 최대 3회 재시도 선차감). 성공 여부와 무관하게 예약량은 반환하지 않는다. 이는 시범 보수 한도이며 API 업체별 정책·비용의 보장은 아니다. 호스팅 인증 전 요청 비용, Firestore/Auth 과금 등은 별도.
- 앱 요청은 types와 선택 항목에 필요한 city/stockTickers/newsLanguage만 전송. 기존 로컬 식별자, 날짜, 시간대, 키워드, 일정 데이터 제외. 토큰은 HTTPS 승인된 직접 서비스 URL에만 헤더로 보내도록 코드 제한. 실제 Android redirect 동작은 활성화 전 검증.
- 기존 14개 도시 한국어/영문 별칭만 승인하고 미지원 도시를 서울로 바꾸지 않음. 뉴스 ko/en은 한국/미국 *국가별* 주요 뉴스이며 기사 언어 보장이 아님. 뉴스 키워드는 로컬 보관. 주식 1~5개 및 문자 제한.
- 외부 API 타임아웃, 로그 최소화, 제한된 캐시 및 HTTPS 뉴스 링크. 개인정보처리방침 원본과 보관본 동기화. 이전 배포본과 새 보안 경로는 구분.

## 운영 활성화 체크리스트 (이번 개발에 포함되지 않음)
1. 실제 Firebase/Cloud Functions 프로젝트, 계정 인증 및 승인 UID 목록 확인. BRIEFING_ENABLED와 BRIEFING_ALLOWED_UIDS는 서버에만 설정. 빈 값·기본값으로 활성화하지 않는다. 환경변수의 실제 값은 커밋·로그·출력 금지.
2. 서명 Android 앱에서 App Check/Play Integrity 도입 및 운영 허용 정책, 토큰 전송·redirect 차단 확인. 승인 계정 시범 검증 외 일반 공개 금지.
3. Cloud Functions 서비스 계정 권한, Firestore 격리·카운터 장애/동시 요청, 로그·삭제 정책, 운영 할당량, Cloud Billing 비용 알림 및 필요 시 인프라 차단을 검증. 일일 카운터는 고정 키 갱신 방식으로 UID 해시 기록은 운영자가 별도 정리.
4. 공급사 API 플랜 및 데이터 최신성/지역 지원 확인. NewsAPI 운영 이용 권한 등 별도.
5. 현재 배포 AAB의 실제 환경과 Play 데이터 보안·개인정보 신고 대조. 기본 배포의 서버 미연결 상태를 변경하지 않는다.
6. 사용자 별도 승인 전 Functions/Firestore/Play 배포 금지.

## 자동 검증
- 루트 Node 클라이언트 요청·URL 회귀 테스트.
- Functions Node 24 TypeScript 빌드 및 인증/한도/검증 오프라인 테스트. 실제 서비스 호출과 비용 발생 없음.
- 별도 Firebase 운영 동시성 및 Android 실측은 승인된 시범 단계에서 진행. CI 성공을 운영 활성화 증거로 간주하지 않음.
