# PO-AI-02 — 기기 AI 모델 성능·다운로드 최적화 (2026-11-24)

## 적용 범위
- 5개 모델 카탈로그·공식 URL·고정 SHA-256·LiteRT CPU 런타임 유지. 모델 관리 화면의 진행률 확인에서는 전체 검증 직후 파일 경로/크기/mtime/dev/inode/ctime/기대 SHA가 같은 경우에만 프로세스 메모리의 5분 상태 캐시 재사용. 목록 캐시만으로 실행·선택하지 않음.
- 다운로드 완료, 명시적 검증, 기본 선택, 매 추론 전 전체 SHA-256 확인 유지. 파일 변경 확인, 해시 블록별 코루틴 취소 확인, 설치/교체/삭제/추론 파일 사용을 같은 모델 작업 Mutex로 보호. Nano/LiteRT 추론은 공통 단일 실행 gate. Native JNI 중단은 호출이 반환될 때까지 지연될 수 있음.
- RAM 확인을 추론 gate 확보 후 및 해시 후에 수행. 기기 전체 여유 RAM/총 RAM/남은 저장 공간 및 카탈로그 최소 여유 RAM 표시. 시스템 Nano 가능 우선, 다음으로 현재 자원에 적합한 작은 설치 모델/설치 후보 추천. 추천은 정확도·응답 속도 실측 순위가 아니며 자동 선택하지 않음. 일반 기능·로컬 파서는 계속 사용 가능.
- 설치 용량 300MB 여유 및 다른 활성 다운로드의 잔여 바이트 합산. Wi-Fi·비과금·비로밍 제한 유지/강화. Android가 대기한 작업은 기존 요청 ID로 이어가고, 종료된 오류는 사용자가 재시도. Enqueue 직후 ID 저장 전 중단 시 동일 승인 URL/제목/대상 파일의 기존 DownloadManager 요청 복구; 모호/미확인 기록은 차단. 다운로드 완료 파일 검증과 명시적 삭제/오류 상태 유지.
- 화면이 활성일 때만 4초 진행률 조회, 중복 조회 병합, 테스트/설치 중 중복 조작 차단, 화면 이동/백그라운드 후 비교 중지 및 늦은 결과 무시. 숨긴 화면에서 새 폴링 없음(이미 시작된 네이티브 작업은 반환될 수 있음).
- 테스트 전체 소요 시간과 LiteRT의 실제 SHA 검증/엔진·대화 준비/응답 생성 시간, 실행 전·엔진 종료 후 기기 전체 여유 RAM을 표시. RAM 스냅샷은 모델별 피크 RAM/RSS가 아니며 Gemini Nano에는 계측하지 않은 항목을 표시하지 않음. 벤치마크에는 일정 저장·네트워크 AI fallback 없음.

## 검증
- Kotlin: 용량 예약, RAM·저장 공간 추천, 상태 캐시 무효화/만료, 해시 취소. 기존 정상/손상/크기 SHA 테스트 유지.
- Android API35 기존 다섯 모델 런타임 probe에 작은 합성 파일 lease·같은 크기 변조 재검증·기기 RAM 조회 추가. 실제 모델 파일이 없는 경우 추론 성공으로 간주하지 않음. 실파일 네트워크 다운로드·Wi-Fi 중단·기기별 실제 처리 시간 및 최대 RAM 사용량은 삼성/ARM64 실기기 최종 검증 사항.
- Node: 측정값 표시, 숨은 화면 폴링 제한, 검증/실행 분리와 기본 선택 조건.
- 서명·Play/Firebase 배포 및 전체 3환경 QA 정책 변경 없음.
