## 대상

CAL-01~CAL-07: 달력의 중복 제목, 주간 간격, 주말 시각 구분, 날짜별 일정 건수, 초기 화면 목록 접근성, 실제 일정이 선택된 날짜의 증빙 부족.

## 구현

1. 상단 브랜드 헤더를 보존하면서 본문 제목을 **캘린더**로 축약하고 중복 안내를 제거했습니다.
2. 기존 `react-native-calendars`의 월 이동·날짜 선택·6주 표시는 유지한 채 주간 수직 간격을 줄였습니다. 날짜 자체의 터치 대상을 강제로 축소하지 않습니다.
3. 일요일 요일 헤더에 위험 색 토큰, 토요일에 브랜드 블루 토큰을 적용했습니다. 실제 일정 점은 기존 개수(최대 3개)·다크 모드 대비를 유지합니다.
4. 일정 점이 존재할 때에만 설명을 표시해 빈 달력의 하단 공간을 절약합니다.
5. 선택 날짜 요약의 간격·배지 크기를 줄이고 접근성 레이블은 유지합니다.
6. 선택된 날짜의 일정 목록은 **시작 시각 오름차순**으로 정렬합니다. 각 목록 행은 최소 68dp 이상, 긴 제목 줄바꿈·반복·알림·상세 이동을 보존합니다.
7. 빈 날짜 안내를 한 문장으로 줄이고 로딩·오류 상태는 구별합니다.
8. 독립된 Android 테스트 앱에 실제 오늘 일정 1건/3건을 저장한 후, 선택된 오늘 달력 2장 및 스크롤한 3건 목록 1장을 추가 캡처하도록 구성했습니다. 이전 52장 + 신규 3장 = **필수 55장**입니다.

## 기능 보존

- 기존 하단 **홈·일정·설정** 3탭, 일정 CRUD, 월/연 반복, 알림, 로컬 시간대, 빠른 입력, Android 네이티브 모달, Gemini Nano 경로 및 Play 내부 테스트 정책 유지
- 시안에만 있는 장소·할 일·별도 AI 채팅·외부 캘린더 연결 기능 미추가
- 사용자 단말의 실제 일정 데이터에 직접 쓰지 않음. 신규 테스트 데이터는 GitHub Actions 격리 에뮬레이터에서만 생성

## 완료 판정

1. Node UI 테스트 및 TypeScript / ESLint / Expo Android 번들 검사 성공
2. Android Kotlin 단위 테스트와 디버그 APK 빌드 성공
3. Android 29 에뮬레이터 캡처 55장, 누락 0장, 경고 0건
4. 1건·3건 선택일 요약과 스크롤 목록에 실제 일정 정보가 노출되는지 확인
5. PR 검증 통과 후 `main` 병합. Play 내부 테스트의 실게시 성공 여부는 별도 워크플로 API 단계로 확인하며 **비공개 테스트에 임의 배포하지 않음**
