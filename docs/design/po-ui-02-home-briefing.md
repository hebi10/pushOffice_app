# PO-UI-02 · 홈·브리핑 화면 리디자인

> 2026-11-05 · 2차 리디자인 2/8단계 · 기준 PR 브랜치: `feat/push-office-home-briefing-po-ui-02-20261105`

## 가이드 및 적용 원칙
- [홈·브리핑 디자인 가이드](https://drive.google.com/file/d/1YONvqA9ZavAAappxtmOKZuyMJX8IjRUO/view)
- 홈의 정보 구조는 **인사말·날짜 → 빠른 입력 → 오늘 브리핑 → 다음 일정 → 오늘 일정 → 외부 정보** 순서를 따른다.
- `src/lib/designTokens.ts` 및 `AssistantButton`, `AssistantCard` 등 1단계 공통 컴포넌트를 사용한다.
- 실제 앱 기능으로 없는 할 일·집중 시간·회의 장소는 가이드에 표시되어 있어도 생성하지 않는다. 기존 하단 탭 3개는 변경하지 않는다.

## 구현 내용

| 영역 | 반영 내용 | 근거 데이터/동작 |
|---|---|---|
| 상단 인사말 | 브랜드 및 날짜·인사말의 대비와 간격 유지 | 로컬 `now`, 기존 `ScreenIntro` |
| 빠른 일정 입력 | 한 개의 강조된 CTA, 텍스트·음성 가능 안내 | 기존 `PushOfficeNative.openQuickEntry` 호출 |
| 오늘 브리핑 | 일정 개수를 칩으로 강조, 긴 일정 목록 중복 표현 제거 | 오늘 발생 인스턴스 `todayItems`, 기존 로컬 AI 요약 유지 |
| 다음 일정 | 시작 시간(종일 구분), 유효한 종료 시간, 제목, 날짜, 반복 상태 강조 | 기존 `nextSchedule`, `endAt`, 상세 이동 |
| 오늘 일정 | 모든 발생 일정 목록 유지, 시간 정렬, 반복·알림 상태·긴 제목 표시 개선 | `projectOccurrences` 및 `ScheduleItem` |
| 외부 브리핑 | 외부 정보 섹션으로 분리, 수동 호출·로컬 일정 비전송 안내 유지 | 기존 `external.mutate`와 데이터 결과 카드 |
| 예외 상태 | 로딩·조회 오류·일정 0건·다음 일정 없음 구분 | 기존 `useSchedules` 상태 및 발생 목록 |

## 기존 로직 보존
- 일정 저장·알림·반복·타임존·원본 ID와 네이티브 브리핑 인터페이스를 변경하지 않았다.
- 사용자가 요청하기 전에는 날씨·뉴스·주식을 가져오지 않는다.
- `nextSchedule`이 계산하는 반복 일정의 날짜·시간을 그대로 사용하고, **종료 시간이 시작 시간보다 뒤인 경우에만** 종료 시각을 표시한다.
- 실제 일정에 `id`가 없을 경우 상세 진입 버튼을 비활성화한다.
- 새 라이브러리·탭·호출 API·폰트 파일·애니메이션을 추가하지 않았다.
