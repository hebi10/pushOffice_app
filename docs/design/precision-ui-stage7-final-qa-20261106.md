## 범위와 판정 기준

단일 Android 에뮬레이터로 확인 가능한 범위와 실제 기기·Play 사용자 계정이 필요한 범위를 분리합니다. 기능·데이터·서명·배포 정책을 변경하지 않고 화면 사용성과 검사 근거를 보강합니다.

## 7단계 수정

1. **태블릿 크기 정보 밀도:** 홈·캘린더·설정·상세 화면의 공통 콘텐츠 폭을 최대 720dp로 제한하고 화면 중앙에 배치합니다. 스마트폰에서는 100% 너비를 유지합니다. 보존 브리핑·채팅 화면에도 같은 최대 폭을 사용합니다.
2. **큰 글꼴:** Android 29 에뮬레이터의 시스템 `font_scale=1.3`으로 홈·캘린더·설정·네이티브 입력 선택·편집 5화면을 실제 캡처합니다. 터치·탭 내비게이션과 필수 입력 진입을 검증한 뒤 1.0으로 원복합니다.
3. **태블릿급 뷰포트:** Android 에뮬레이터의 화면 크기를 `1440x2160 @ 280 dpi`로 변경해 홈·캘린더·설정·네이티브 입력 선택·편집 5화면을 캡처하고 원래 `720x1600`으로 복구합니다. **화면 크기 변경 시험이지 실물 태블릿 시험은 아닙니다**.
4. **위젯:** 실제 설치된 Android 앱의 `dumpsys appwidget`에서 `ScheduleWidgetProvider`, `ScheduleAgendaWidgetProvider`의 등록을 점검합니다. 레이아웃·색상·이벤트·텍스트/음성 `PendingIntent` 관련 이전 회귀 검사를 유지합니다.
5. **캡처 신뢰성:** 기존 40개 + 신규 10개 필수 PNG(총 50장), 큰 글꼴/태블릿 화면 픽셀 크기, 누락 0건, 경고 0건, 기기 매트릭스 보고서 `ui-captures/device-matrix.json` 생성 여부를 자동 검증합니다.
6. **브랜드·디자인:** 기존 앱 아이콘·적응형 아이콘·스플래시 자산과 브랜드 블루 팔레트를 보존하고, 기존 1~6단계의 UI 검사를 모두 실행합니다.

## 자동으로 완료 판정 가능한 항목

- 기존 Node 테스트 / TypeScript / ESLint / Expo Android JS 번들.
- Android Kotlin 단위 테스트 및 디버그 APK 빌드.
- Android 29 에뮬레이터 화면 50장, 기존 라이트/다크/소형 화면 + 큰 글꼴 + 태블릿 크기.
- Android 위젯 2종의 설치 등록 확인.
- `main` PR squash 병합 및 자동 Play 테스트 트랙의 실제 게시 완료 단계 확인.

## 자동화만으로 최종 완료를 확정할 수 없는 항목

- 사용자 실제 휴대전화·태블릿의 UI 및 접근성(TalkBack, 글꼴/디스플레이 배율).
- Samsung One UI 등 제조사 런처에서 위젯 **실제 배치·크기 변경·클릭·정보 업데이트**.
- 실기기 마이크·음성 권한·기기 내 한국어 음성 인식.
- Gemini Nano **실제 모델 가용성·추론**. 지원하는 하드웨어/Play Services 조건이 필요합니다.
- Google Play 테스트 사용자 계정의 설치·기존 버전에서 업데이트·화면별 확인.
- 로컬 데이터 복원이나 알림의 장기 실행·절전/재부팅 회귀(물리 기기 필요).

위 미검증 항목은 `device-matrix.json`에 명시하고 **성공으로 표기하지 않습니다.** 자동 검증 성공과 실제 사용자 기기 최종 출고 승인을 동일하게 취급하지 않습니다.
