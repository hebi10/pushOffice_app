# PO-UI-03 · 빠른 일정 입력 전체 흐름 리디자인

> 기준: 2026-11-05 · 리디자인 3/8단계 · 디자인 가이드: [Google Drive](https://drive.google.com/file/d/18R19XIOnVvAl4ih7OsoVrQw4GCXgCfRy/view)

## 목표 및 제약
기존 Android 네이티브 `QuickEntryActivity`의 **입력 방식 선택 → 편집 → 저장 전 확인 → 저장** 흐름을 제품 디자인 가이드와 일치시킵니다.
데이터 스키마, 로컬 저장, 시간대, 반복 일정, 음성 인식 권한, Gemini Nano 해석은 변경하지 않습니다.

## 적용

| 화면 | 디자인 변경 | 기존 동작 |
|---|---|---|
| 입력 방식 선택 | 아래에서 올라오는 바텀시트형 레이아웃, 가운데 일러스트, 상단 닫기, 텍스트(Primary)·음성(Secondary) 카드 | 키보드 입력·기기 내 음성 입력 선택을 유지, 화면을 열 때 녹음 시작하지 않음 |
| 텍스트·음성 편집 | 그룹별 제목/설명, 안내 상태 패널, 음성·AI 도우미 버튼 2열, 내용을 확인하는 주요 버튼을 하단 배치 | 텍스트 수동 편집, 기기 내 한국어 인식, AI 해석/취소, 인식 불가 상태 보존 |
| 저장 전 확인 | 메시지/시간대 안내, 제목·날짜·시간 개별 카드, 날짜·시간 선택, 반복 선택 카드, 저장·되돌아가기 분리 | 날짜/시간 직접 입력, 달력·시간 선택, 반복 선택, 검증 및 저장 코드 그대로 |
| 일정 변경 비교 | 원래 일정 이름과 변경 전·후 시각을 별도 행으로 표시 | 변경 대상 선택, 기존 ID/시간대/종료 시각, 원본 변경 감지 및 직렬 저장 보존 |
| 작은 기기·다크 모드 | 바텀시트 최대 높이 제한, 저장 전 확인 스크롤, 검은 글자·파란 배경 대비, 다크 모드에서 밝은 이미지 미노출 유지 | 시스템 뒤로 가기/기기 설정 테마/입력 과정 복귀 유지 |

## 바텀시트 적용 범위와 위험 관리
- `chooser()`에만 `Gravity.BOTTOM`을 사용합니다. 높이는 시스템 영역을 제외한 가용 공간으로 제한하며 세로 스크롤을 지원합니다.
- `page()`에서 `Gravity.CENTER`를 다시 지정해, 키보드 및 날짜·시간 입력이 있는 편집/확인 화면은 기존 중앙 다이얼로그와 `adjustResize` 동작을 유지합니다.
- 기존 다이얼로그를 전면 교체하거나 새 서드파티 라이브러리를 추가하지 않았습니다. 설치된 Android 기본 `DatePickerDialog`·`TimePickerDialog` 및 시스템 권한창은 그대로 유지합니다.
- 홈·위젯·빠른 설정 타일이 공유하는 동일한 `QuickEntryActivity` 진입점을 유지합니다. 화면 선택·닫기·뒤로 가기 및 앱 생명주기 정리도 기존 경로를 사용합니다.

## 검증 기준
- `tests/ui-quick-entry-stage3.test.mjs`에 UI 계층과 일정 안전 처리(직렬 변경·오래된 수정 대상 재확인) 회귀 조건 추가.
- `Push Office UI validation`에서 Node 회귀, TypeScript·ESLint·Expo Android 번들, Kotlin 단위 테스트·디버그 빌드를 확인.
- `Push Office UI screenshots`를 확장해 음성 선택 진입, 일반 편집, 날짜/시간 확인, 다크 모드, 좁은 640px(약 366dp) 세로 화면을 검수.
- 큰 글꼴·회전·태블릿과 실제 음성 입력 모델 다운로드의 전체 실기기 테스트는 8단계에서도 추가 검증합니다.

## 범위 외
- 새 일정의 종료 날짜/시간 입력 데이터 모델 추가, 새 인식 엔진 다운로드 방식, 다른 앱과의 공유, 미구현 탭·기능 추가는 별도 기능 요구에 해당합니다.
- Play 내부 테스트에 실제 업데이트됐는지는 GitHub 빌드 성공과 별도로 확인해야 합니다.
