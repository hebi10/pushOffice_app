# Push Office · 알림 일정 추천과 로컬 AI 보완 (2026-11-08)

## 목적
- Gemini Nano 지원 기기에서는 사용자가 명시적으로 모델 다운로드를 요청할 수 있게 한다. \`AVAILABLE\`/\`DOWNLOADABLE\`/\`DOWNLOADING\`/\`UNAVAILABLE\`을 구별한다.
- Android 빠른 설정 타일의 사용 여부를 설정에서 변경한다. 타일 배치는 Android 시스템의 사용자 확인이 필요하다.
- Android 알림 접근 권한과 별도 기능 동의가 모두 있는 사용자에게만 알림 후보 추천을 제공한다. 승인 전 자동 저장은 절대 하지 않는다.

## 데이터 경계
- Android NotificationListenerService만 알림 수신을 관찰한다. 서비스의 예약/상시 실행 또는 강제 권한 부여는 없다.
- 명시적 날짜·시간이 없거나 보안·금융·OTP 관련 문구가 있는 알림은 일정 후보 분석에서 제외한다. 탐지 규칙은 완벽하지 않다.
- AI 사용이 가능하면 on-device Gemini Nano 파서로 분석하고, 실패하거나 미지원이면 기존 오프라인 규칙 파서를 사용한다.
- 앱 전용 SharedPreferences에 최대 24건을 48시간 한도로 보관한다. 사용자 거절 및 기능 OFF에서 후보를 삭제한다.
- 중복 방지용 해시를 최대 200건 보관한다. 후보 내용은 원격 AI·Firebase·외부 브리핑으로 전송하지 않는다.

## 승인 UX
- 설정 > 알림에서 일정 추천 > 추천 일정 후보에서 분석 출처(기기 AI/규칙)와 원문 일부/예정 시간을 확인한다.
- 후보의 '검토 후 저장'은 기존 네이티브 일정 입력 폼을 열어 제목/시각 수정 후 명시적으로 저장한다.
- 일정 저장은 기존 ScheduleRuntime 경로로 알람 및 위젯 동기화를 수행한다. 같은 제목/시각의 중복 저장은 막는다.
- 백그라운드 분석은 Android의 알림 수신 시 실행을 시도할 뿐, 항상 실행을 보장하지 않는다.

## 출시 전 필수 검증
1. Android 빌드 + Kotlin 유닛 테스트 + React Native 타입/ESLint 테스트 통과.
2. API 26/29/35/36 실제 OS 설정 화면을 통한 권한 허용/철회 및 타일 추가/해제 확인.
3. 지원/미지원 기기에서 Gemini Nano 다운로드 시작·완료·실패와 앱 재실행 상태를 검증.
4. 알림 허용 OFF/ON, 알림 그룹/금융/OTP/일정 메시지·중복·후보 만료와 승인/거절을 실기기로 검사.
5. Play Console 데이터 보안 설문, 정책 및 실제 개인정보처리방침 링크의 배포 확인 후 테스트 트랙 출시.
