Push Office 개인정보처리방침

시행일: 2026년 11월 3일 · 최종 수정일: 2026년 11월 8일
대상 앱: Push Office · Android 패키지: com.hebi96.pushOffice_app

이 방침의 운영 주체는 GitHub 계정 hebi10의 Push Office 운영자(이하 “운영자”)입니다. 지원 및 개인정보 문의는 asdlkj0104@gmail.com으로 보낼 수 있습니다.

Push Office는 새 계정이나 로그인 없이 기기에 일정을 저장합니다. 음성 입력과 기기 AI는 시스템 서비스를 사용하며, Google ML Kit는 별도의 식별자·진단 정보를 처리합니다. 날씨·뉴스·주식의 외부 브리핑은 사용자가 직접 요청하는 선택 기능입니다.

1. 기기에 저장하는 정보와 이용 목적

일정 관리와 알림 제공을 위해 일정 제목, 날짜·시간, 시간대, 반복·알림 설정, 생성·수정 시각과 입력 원문(sourceText)을 앱의 로컬 SQLite 데이터베이스에 저장합니다. 음성으로 입력한 경우 인식된 텍스트가 입력 원문에 포함될 수 있습니다.

앱 설정, 브리핑 기록, 이전 버전 기록과 가져오기 상태는 기기의 앱 저장소에도 보관합니다. 기록을 구분하기 위해 무작위 앱 설치 식별자(UUID)를 만들어 저장합니다. 이 식별자는 아래의 외부 브리핑을 요청할 때도 전송됩니다.

기본 일정의 입력·확인·수정·삭제와 알림은 외부 브리핑 없이 사용할 수 있습니다. 운영자가 사용자의 로컬 일정 데이터베이스를 원격으로 열람하는 기능은 없습니다.

2. 음성 입력과 플랫폼 서비스

음성 입력은 사용자가 시작 버튼을 누르고 마이크 권한을 허용할 때 사용합니다. 앱은 Android의 기기 내 음성 인식 API로 한국어 인식을 요청하며, 지원 여부와 설치된 한국어 모델을 확인하지 못하면 텍스트 입력을 안내합니다. 온라인 음성 인식으로 자동 전환하는 경로는 없습니다.

음성은 운영자 서버가 아닌 기기의 플랫폼 음성 인식 서비스에 전달되어 처리됩니다. 앱 자체는 녹음 파일을 저장하거나 오디오를 운영자 서버·외부 AI 서버로 업로드하지 않습니다. 인식된 텍스트는 사용자가 확인·저장한 일정의 원문으로 남을 수 있습니다. 입력 창을 떠나거나 앱이 비활성화되면 앱의 음성 인식을 중지합니다.

플랫폼 서비스의 처리는 기기 제조사, 설치된 인식 제공자와 시스템 설정의 영향을 받습니다. Android는 일반적인 음성 인식 서비스에 원격 서버 처리가 포함될 수 있다고 설명합니다. Push Office가 선택하는 기기 내 인식 경로와는 구별되지만, 언어 모델 다운로드·업데이트나 제공자 자체 진단을 위한 외부 통신까지 앱이 통제하거나 차단하는 것은 아닙니다. 기기 전체에서 어떤 정보도 외부로 처리되지 않는다고 보장하지 않습니다. 사용 중인 음성 인식 서비스의 개인정보 설정과 정책도 확인해 주세요.

참고: Android 음성 인식 API 안내. 마이크 권한을 허용하지 않아도 텍스트 입력을 사용할 수 있습니다.

3. 기기 AI와 Google ML Kit의 식별자·진단 정보

지원 기기에서는 Gemini Nano와 Google ML Kit GenAI를 이용해 입력을 해석하거나 일정을 요약할 수 있습니다. Google의 ML Kit 공식 설명에 따르면 입력 내용과 생성 결과는 기기에서 처리되며, ML Kit가 그 내용과 결과를 Google 서버로 보내지 않습니다.

이와 별도로 ML Kit는 진단과 사용 분석을 위해 다음 정보를 수집·처리합니다.

  • 기기 제조사·모델·운영체제·지원 하드웨어와 앱 패키지·버전 정보
  • 사용자·기기 또는 기타 식별자와 설치별 식별자
  • 지연 시간 등 성능 지표, API 설정, 입력·출력의 크기, 기능 버전과 설정된 언어
  • 기능 초기화·모델 다운로드·리소스 해제 등의 이벤트와 오류 코드

지원 기기에서 사용자가 설정의 다운로드 버튼을 누르면 Android AICore를 통해 Gemini Nano 모델 자산 다운로드를 요청합니다. 앱이 모델 파일을 직접 호스팅하거나 외부 AI 서버로 알림 본문을 전송하지 않습니다. 다운로드·이용 가능 여부는 Android 및 AICore 지원 상태에 따라 달라집니다.

입력·출력의 크기는 실제 일정 내용이나 생성된 문장 자체와 구별됩니다. 앱은 홈과 설정 화면에서 기기 AI의 준비 상태를 자동 확인하며, 이 SDK 경로의 진단 처리를 끄는 앱 내 설정은 제공하지 않습니다. Google은 이 정보를 API의 성능 확인, 유지·개선과 오용 방지 등에 사용한다고 설명합니다.

Google은 공개된 ML Kit 진단 정보의 전송에 HTTPS를 사용하고 ML Kit가 해당 정보를 제삼자에게 전달하지 않는다고 설명합니다. Google이 처리하는 정보의 보관과 관리에는 Google의 관련 정책이 적용됩니다. 운영자는 Google의 진단 정보에 대해 확인되지 않은 일률적인 보관 기간이나 삭제 완료 시점을 약속하지 않습니다.

참고: ML Kit 데이터 공개 안내, ML Kit 약관 및 개인정보 설명, Google 개인정보처리방침.

4. 선택적 다른 앱 알림 접근 및 일정 후보 추천

이 기능은 기본값이 꺼짐입니다. 앱은 권한 요청과 기능 활성화 전에 접근 범위·이용 목적·보관 및 삭제를 설명하는 별도 안내창을 표시합니다. 사용자가 Android 시스템의 별도 알림 접근 권한을 부여하고 앱에서 ‘백그라운드 일정 후보 분석’을 직접 켠 경우에만 수집을 시작합니다. 시스템 권한만 허용했다고 자동으로 일정 분석을 시작하지 않습니다.

알림 접근 권한을 부여하면 Android는 다른 앱의 알림 제목·본문 등 민감한 알림 내용에 접근할 수 있도록 허용합니다. Push Office는 이 중 날짜·시간을 포함한 일정 관련 내용만 기기에서 선별하며, 인증번호·금융 등 일부 민감한 문구는 규칙으로 제외합니다. 다만 모든 민감 알림을 완벽히 식별하거나 제외할 수 있다고 보장하지 않습니다.

필터를 통과한 알림은 백그라운드에서 로컬 규칙 파서로 일정 후보를 추출합니다. 기기 AI가 지원되는 경우 앱을 연 상태에서 사용자가 개별 후보의 ‘기기 AI로 다시 분석’을 요청하면 Gemini Nano로 제목과 시각을 재분석할 수 있습니다. AI가 지원되지 않거나 분석이 실패하면 기존 규칙 분석 결과를 유지합니다. 결과로 일정 후보 제목, 예정 시각, 알림 발생 앱 이름, 원문 일부 및 분석 방식이 기기 내부 앱 전용 저장소에 저장됩니다. 일정 후보는 최대 24건이며 수집 후 48시간이 지나면 목록을 조회하거나 저장할 때 제거합니다. 이미 처리한 알림을 중복 추천하지 않도록 내용에 기반한 비가역 식별값도 최근 최대 200건까지 앱에 보관합니다.

사용자는 추천 후보를 열어 제목·날짜·시간을 수정하고 명시적으로 저장하거나 거절·삭제할 수 있습니다. 승인 전에는 일정 데이터베이스나 알람에 자동으로 추가하지 않습니다. 기능을 끄면 보관 중인 일정 후보와 중복 방지 기록을 즉시 삭제합니다. 기존에 승인해 저장한 일정은 별도의 일정 삭제를 하기 전까지 유지됩니다. Android 알림 접근 권한은 기기 설정에서 별도로 철회할 수 있습니다.

새 알림 수신 시에만 로컬 규칙 기반 분석 작업을 시도하며, 상시 실행되는 서비스나 원격 업로드를 사용하지 않습니다. Gemini Nano는 Android 정책상 백그라운드에서 사용이 제한될 수 있으므로 사용자가 앱을 연 뒤 직접 AI 재분석을 실행합니다. 운영체제의 절전, 앱 강제 종료, 기기 AI 지원 여부에 따라 백그라운드 수집 또는 분석이 지연·실패할 수 있습니다.

5. 선택적 외부 브리핑과 서버 처리

날씨·뉴스·주식 항목은 새 설치에서 모두 꺼져 있습니다. 외부 서비스 주소가 앱에 구성되어 있고, 사용자가 항목을 설정한 뒤 ‘외부 브리핑 불러오기’를 누르면 해당 서비스로 요청합니다. 주소가 구성되지 않거나 연결되지 않으면 외부 브리핑을 사용할 수 없습니다.

외부 브리핑 요청에서 처리하는 정보
정보처리 목적과 범위
무작위 설치 식별자, 기록 소유 유형, 날짜·시간대브리핑 요청 및 기록 구분. 요청의 ownerId에 무작위 식별자가 포함됩니다.
선택 항목, 도시, 관심 주식 종목, 뉴스 키워드·언어사용자가 선택한 정보의 요청 설정으로 전송됩니다. 뉴스 키워드·언어는 현재 서버 구현에서 결과에 모두 반영되지 않더라도 요청에 포함됩니다.
IP 주소와 요청 로그서버가 통신 과정에서 IP 주소를 받을 수 있습니다. 포함된 서버 구현은 IP를 메모리의 요청 제한에 사용하고 도시·선택 항목을 로그에 기록합니다. 호스팅 환경에서 별도의 접속·오류 로그가 생성될 수 있습니다.

일정 제목, 일정 입력 원문과 음성은 외부 브리핑 요청에 포함하지 않습니다. 날씨 도시는 사용자가 설정하며 앱이 실제 기기 위치를 측정하는 기능은 없습니다.

서버 구현은 선택 항목에 따라 OpenWeather에 도시 기준 좌표, Alpha Vantage에 관심 종목을 요청하고 NewsAPI에서 뉴스를 가져옵니다. 서버에 OpenAI 사용 설정이 있으면 날씨·뉴스·주식 결과를 요약하기 위해 OpenAI에 보낼 수 있습니다. 이 요약 입력에는 앱의 로컬 일정이나 음성이 포함되지 않습니다.

이 기능의 실제 처리 사업자·서버 위치·인프라 로그 보관 기간은 연결된 서비스와 배포 설정에 따라 달라집니다. 이 방침은 확인되지 않은 서버 위치나 고정 보관 기간을 제시하지 않습니다. 해당 서비스의 처리·보관·삭제 범위를 확인하려면 지원 이메일로 문의해 주세요. 외부 정보가 필요하지 않으면 브리핑 요청을 하지 않고 로컬 일정 기능을 사용할 수 있습니다.

6. 이전 Firebase 계정과 기록 가져오기

이전 버전에서 Firebase를 사용한 상태가 남아 있거나 사용자가 가져오기를 재시도하면, 앱은 구성된 Firebase 서비스와 기존 로그인 상태를 확인할 수 있습니다. 기존 계정이 확인되면 해당 계정 식별자·인증 상태를 이용해 일정과 설정을 읽어 기기로 가져옵니다. 이전 복구 대기 상태가 있는 경우 앱 시작 후 자동으로 시도할 수도 있습니다.

이 과정에서는 Firebase Authentication과 Firestore가 인증·조회에 필요한 계정 식별자, 통신·기기 관련 정보를 처리할 수 있습니다. 새 사용자 화면은 새 Firebase 계정을 만들지 않습니다. 가져오기는 원격 기록을 읽는 작업이며 원격 원본을 수정하거나 삭제하지 않습니다.

로컬 일정이나 앱을 삭제해도 이전 Firebase 계정과 서버 기록은 자동 삭제되지 않습니다. 이전 기록의 보관·삭제에 관한 문의는 지원 이메일로 보내 주세요. 기기에만 있는 데이터와 서버에 있는 이전 기록은 구별하여 확인해야 합니다. 참고: Firebase 개인정보 및 보안 설명.

7. 권한, 알림과 광고

  • 다른 앱 알림 접근: 사용자가 별도 승인한 경우에만 기기의 알림 내용을 읽고 일정 후보를 만듭니다. 앱 내 분석 토글은 기본적으로 꺼져 있으며 언제든 끌 수 있습니다.
  • 마이크: 사용자가 시작한 음성 입력에 사용하며, 기기 설정에서 권한을 취소할 수 있습니다.
  • 알림: 일정·재알림·아침 일정 브리핑을 표시합니다. 앱 설정에서 기능을 끄거나 기기 설정에서 권한을 취소할 수 있습니다.
  • 알람·재부팅 수신: 예약 시간의 알림과 재부팅·시간대 변경 후 예약 갱신에 사용합니다. 정확한 알람을 사용할 수 없으면 일반 알람으로 예약되어 전달이 늦어질 수 있습니다.

일정 제목과 시간은 사용자가 추가한 홈 위젯이나 알림 화면에 표시될 수 있습니다. 기기의 잠금 화면 알림 설정에서도 표시 범위를 조절할 수 있습니다.

현재 앱에는 광고 표시, 광고 SDK나 광고 목적의 추적 기능이 없습니다.

8. 보관과 삭제

  • 현재 로컬 일정: 앱의 일정 상세 화면에서 일정과 관련 알림을 삭제할 수 있습니다.
